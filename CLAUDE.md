# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CS604 group project (3 people): fine-grained **10,000-class** image classification by adapting a pre-trained **ViT-B/16** (`timm` `vit_base_patch16_224.augreg2_in21k_ft_in1k`). Two required tracks, each within **2 h x 48 GB VRAM** (about 96 GB-hours; tolerance +-10%; e.g. 4 h on a 24 GB GPU or ~2.4 h on an A100 40 GB):

1. Full fine-tuning.
2. Efficient adaptation: freeze the backbone, train a small set (<5%) of parameters: LoRA, Adapter, AdaptFormer, Prefix tuning, BitFit, selected-layer tuning.

**Parameter-count rule (confirmed by the professor, 11 Oct 2026):** the classifier head (768 x 10,000, ~7.7M params, 8.2% of the model) is **not counted**. Trainable % = adapter params / backbone params (85.8M). This matches the brief's LoRA 0.34% = rank 8 on `qkv`. The head's trainable count is logged separately as `head_params`. Report both in the write-up and say how the head is counted. The professor also ruled (12 Oct 2026) that a different base checkpoint is not allowed, so stay on `vit_base_patch16_224.augreg2_in21k_ft_in1k`; do not try the IN21K-only weights. The <5% limit applies to the efficient-adaptation track only; full fine-tuning (100%) is the other required track and the baseline to compare against.

The brief hints at bf16, gradient accumulation, classifier-head initialisation, PEFT-adapter initialisation and loss design. Reference results from the brief (not bounds; 90%+ is not expected): zero-shot with initialised head 43.7%, full FT 70.8%, LoRA 68.3% (0.34% params). The original brief PDF is deliberately not in the repo (it contains the CodaBench link with a secret key).

## Data (not in the repo; lives on the Colab VM)

- Hugging Face dataset `doem1997/cs604-course-data`: `train.tar.gz` (~40 GB), `val.tar.gz` (~4.4 GB), `train.txt`, `val.txt`; `test.*` appears in Phase 2 (31 Oct).
- Train: 450,000 images, exactly 45 per class, `train/class_XXXX/<uuid>.jpg`, `train.txt` = `path class_id`. Images ~500x400 px, ~90 KB.
- Val: 50,000 images (5/class) and test: 100,000 (10/class) have **labels withheld** (`val.txt` is paths only). Do not label or train on them (README forbids it). There is no local val accuracy: `common/data.py` holds out a fixed labelled slice of train (2 per class = 20k images, seed 0) and every run is scored on that. The CodaBench val leaderboard is the only check on real val.
- Setup: notebook `00` downloads by streaming both archives into `tar` (~10-20 min) to `/content/cs604-course-data` (Colab local disk). The VM disk is wiped on disconnect, so this repeats per new session; the cell skips itself if the `.ready` marker exists. Google Drive (15 GB) is too small for the data: use it only for run outputs.
- Code finds the data via env var `CS604_ROOT` (default `/content/cs604-course-data`).

## Repo layout and how the pieces fit

- `common/` (shared, change only by team agreement; `metrics.count_params` implements the head-excluded counting rule): `data.py` (split, transforms, loaders) -> `build.py` (timm model, optional head init, then the method wrapper) -> `train.py` (loop) -> `metrics.py` (results row) and `submit.py` (CodaBench file). `head_init.py` sets the new head from class means (nearest-class-mean; `head_init_scale: auto` calibrates confidence with leave-one-out CE).
- `methods/`: one file per method, `apply(model, args) -> model`, registered in `methods/__init__.py`. Contract: `model.head` stays trainable. Head init runs *before* the method wraps the model (PEFT copies the head at wrap time). Existing: `full_ft`, `lora` (peft, on the fused `qkv`), `bitfit`, `adaptformer` (parallel bottleneck adapter on every block's FFN, zero-init up-projection; `last_n: N` adapts only the last N blocks). `lora_adaptformer` = LoRA on every `qkv` (hand-written `LoRALinear`, no peft) plus the AdaptFormer adapter on every FFN, in one model; this is the team's main design. `linear_probe` trains only the head (backbone frozen, 0%). Adapter/Prefix are not written yet. `configs/adaptformer_lora_baseline.yaml` is a dead early draft (its method name is not registered); use `lora_adaptformer` / `abl_combined` instead.

Measured adapter share (backbone-relative, head excluded): LoRA r=8 qkv 0.34%, LoRA r=16 qkv 0.69%, LoRA r=116 qkv 4.984% (r=117 is over 5%), AdaptFormer b=64 1.39%, AdaptFormer b=232 4.998% (b=233 is over), LoRA r=12 + AdaptFormer b=208 4.998%, BitFit 0.12%, full FT 100%.
- `configs/*.yaml`: one run each; all keys and defaults are in `DEFAULTS` at the top of `common/train.py`. Command-line `key=value` overrides win. Name prefixes: `abl_*` = ablation (which adapter design, where it goes), `tune_*` = tuning one hyperparameter (learning rate, label smoothing, head settings), `imp_*` = improvement (the best run so far plus one regulariser), `full_ft_*` = the full fine-tuning track, `final_*` = a final model trained on all 45 images per class (no hold-out, leaderboard only). Current configs: `smoke`, `lora_baseline` (rank 8, alpha 16), `full_ft_baseline`, `bitfit_baseline`, `adaptformer_baseline`, `lora_adaptformer` (main design, auto epochs), and the equal-budget ablation trio `abl_lora_only`, `abl_adaptformer_only`, `abl_combined` (all about 5%, lr 3e-4, 10 epochs; only the adapter design differs). `abl_adaptformer_last6` (AdaptFormer in the last 6 blocks only, bottleneck 464, 4.993%) is the depth ablation against `abl_adaptformer_only`. `tune_ls_lr2e4`, `tune_ls_lr1e4`, `tune_ls_lr5e5` and `tune_ls_lr3e5` combine label smoothing 0.1 with a lower learning rate (1e-4 and 5e-5 are level; `tune_ls_lr3e5` was skipped); `tune_head_lr_half` / `tune_head_lr_double` give the head 0.5x / 2x the adapters' learning rate, `tune_ls_lr1e4_init43` adds the 43-image head start to the best recipe, `abl_linear_probe` is the head-only baseline, `tune_head_lr_quarter` / `tune_head_lr_half_init43` continue the head experiments (a slower head was the best change found by 18 Oct), `full_ft_ls_headlow` gives full fine-tuning the same slower head, and `full_ft_ls` is full fine-tuning with label smoothing (fair comparison). `abl_combined` is also the baseline for the tuning configs `tune_label_smoothing`, `tune_lr_low`, `tune_lr_high` and `tune_head_init`: each is `abl_combined` with exactly one setting changed. The `imp_*` configs (`imp_droppath`, `imp_ema`, `imp_mixup`, `imp_trivialaug`, and `imp_ep15_control` as the control for Mixup) are `tune_head_lr_half` with one regulariser added; `full_ft_llrd` is `full_ft_ls_headlow` with layer-wise lr decay. `imp_mixup` and `imp_ep15_control` run 15 epochs and need an A100 40 GB (budget 2.4 h). `final_5pct_trivialaug` is `imp_trivialaug` on all 45 images per class (the final 5% model; A100 40 GB). The fair track comparison uses `full_ft_llrd_10ep` (full fine-tuning at the 5% runs' 10 epochs) and `imp_trivialaug_fullbudget` (the best 5% recipe filling the whole budget like `full_ft_llrd`), both scored at 224 and 288 px.
- `notebooks/`: `00_setup_and_data_check`, `01_throughput`, `02_train_and_submit` (thin runner; the only one you normally need).
- `results/results.csv`: one row per run, columns in `common/metrics.py:RESULT_COLS`. `results/<run>/log.jsonl` keeps each run's training log. `EXPERIMENT_LOG.md` holds the interpretation, the ablation plan and the next runs: read it before choosing an experiment, and add a section for every finished run.

Behaviours worth knowing before editing `train.py`:
- `epochs: null` + `budget_hours: auto` -> the loop measures its own img/s over steps 100 to 300 and sets the number of steps so the run fits 96 GB-hours / GPU size (7% margin); it stops early at 108% of budget. Set `epochs` or `max_train_steps` for fixed-length runs.
- Precision auto: bf16 on compute capability >= 8 (A100/L4/H100), fp16 + GradScaler on T4, fp32 on CPU.
- Resumable: `<out_dir>/latest.pt` (trainable weights + optimizer + step); re-running the same command continues. The frozen backbone is never saved, only trainable tensors (`final.pt`), so `submit.py` rebuilds the model from `config.yaml` + pre-trained weights + `final.pt`.
- `holdout_per_class=0` trains on all 45 images per class (final model only): no evaluation happens, the hold-out columns of the results row stay empty, and `common.evaluate` refuses the run. Checkpoints hold only trainable tensors, so `submit.py` / `evaluate.py` rebuild the frozen backbone from the pre-trained weights.
- LR schedule is per-step linear warmup then cosine, with 4 param groups (head/backbone x decay/no-decay), head LR = `lr * head_lr_mult`. With `layer_decay` set, each group is also split by depth and scaled by `layer_decay ** (layers above)`.
- Opt-in regularisers, all off by default so older configs train exactly as before: `drop_path_rate` (passed to timm), `ema_decay` (EMA of the trainable weights; per-epoch evals, the final eval and `final.pt` use the EMA weights; stored in `latest.pt` for resume), `mixup_alpha` / `cutmix_alpha` / `mixup_prob` (timm `Mixup`, soft-target loss, label smoothing applied inside the mixer), `auto_augment` (`trivial` | `randaug`) and `re_prob` (random erasing) in `data.train_tf`.
- Test size: `common.evaluate <run> --sizes 224 256 288` and `common.submit ... --size N` build the model with timm's `dynamic_img_size` (position embeddings interpolated) and use `data.eval_tf(N)` (resize N * 248/224, centre crop N). At 224 the output is identical to the fixed-size model.

## Commands (run from the repo root)

```
pip install -r requirements.txt                       # timm, peft, pyyaml (Colab has torch)
python -m common.train configs/smoke.yaml out_dir=runs/smoke          # ~minutes, 100 classes, run this first
python -m common.train configs/lora_baseline.yaml out_dir=<drive>/lora who=<you> results_csv=<drive>/results.csv
python -m common.submit <run_dir> --team XX --split val               # writes + validates val_team_XX.txt and .zip
python -m common.submit <run_dir> --team XX --split val --tta flip    # same with mirror averaging (2 passes: report 2x latency)
python -m common.evaluate <run_dir>                                   # hold-out top-1 of a finished run, with and without mirror averaging
python -m common.evaluate <run_dir> --sizes 224 256 288               # same at larger test sizes, with latency per size
python -m common.submit <run_dir> --team XX --split val --size 256    # submission at a larger test size
```
There is no test suite or linter. The smoke config is the pipeline test. Do not run these on the local Windows machine for real work: it has no GPU; all training happens on Colab.

## Colab and VS Code notes

- Compute is a Colab GPU used from VS Code with the official **Google Colab** extension: open the `.ipynb` locally, Select Kernel -> Colab -> New Colab Server (or reuse an existing server so the downloaded data is visible). Only notebooks run on Colab (no remote terminal); use `!` shell cells. Files written on the VM stay on the VM.
- Measured on a Colab **T4**: 25 img/s training (bf16 is emulated there) = ~5 h per epoch. **Unusable; use an A100** (or L4 as fallback) for real runs. The data loader (8 CPU cores) delivered ~880 img/s, so a fast GPU may become loader-bound. Measured on a Colab **A100 80 GB** (bf16, batch 128): about 1,245 img/s for LoRA r=8 and 1,105 img/s for LoRA + AdaptFormer, about 6.9 min per epoch including the hold-out eval. An 80 GB card is counted as 80 GB, so the budget there is 1.2 h (10 epochs of the combined design take about 1.18 h). The first two `epochs: null` runs stopped early (0.76 and 0.93 h of 1.2 h) because the speed probe then used steps 5 to 35, which are slow; it now uses steps 100 to 300 (verified on 11 Oct: the full fine-tuning run used 1.13 h of 1.2 h). Notebook 02 uninstalls Colab's old `torchao`, which breaks the peft import.
- Notebook 02, first cell: `CONFIG` (which yaml), `RUN` (output folder name; empty = same as CONFIG), `WHO`, `TEAM`, `EXTRA` (overrides). Use a **new** `RUN` whenever you repeat a config (pilot, changed lr), otherwise the run resumes the old checkpoint. Smoke test: leave `RUN` empty. Trap: if `RUN` still holds the name of a finished run while `CONFIG` is new, the run loads the old checkpoint, sees it is already complete, and reports the OLD model's numbers under the new name without training. When switching `CONFIG`, set `RUN = ""`.
- Outputs always go to Google Drive: `My Drive -> cs604_runs -> <RUN or CONFIG>` (checkpoints, log, curves, results row, submission zip). The notebook fails with an error if Drive is not mounted, instead of silently using the VM disk.
- Disconnects kill the run; re-running the notebook resumes from the last checkpoint on Drive, after the data is re-downloaded. Terminate idle sessions (Runtime -> Manage sessions) so credits are not wasted.
- Trap: if only the VS Code connection drops, the training process may still be running on the VM. Re-running the train cell then starts a SECOND process from the last checkpoint in the same folder; both share the GPU and write the same log and results (happened in `imp_droppath`). Before re-running, check with `!pgrep -af common.train`: if a process is listed, wait for it instead.
- Colab credits are per person, so the 3 of us can run experiments in parallel. One account could not start a second GPU server while a run was going ("Unable to assign server. You have too many"); never click "Remove Server" during a run, it can remove the server that is training.

## Conventions for anyone (human or agent) working here

- **Status (23 Oct 2026): the pipeline works end to end on an A100**, including the submission file (runs trained and accepted by CodaBench). Hold-out results (all in `results/results.csv`; details in `EXPERIMENT_LOG.md`):
  - Baselines: LoRA r=8 68.78%; full fine-tuning (required track) 72.53%, and 73.98% with label smoothing (`full_ft_ls`). **Best full fine-tuning: `full_ft_llrd`, 76.26%** (layer-wise lr decay 0.75, slower head, label smoothing; it filled the 2.4 h budget of an A100 40 GB: 18.2 epochs), the best run of either track at 224 px.
  - Equal 5% budget, untuned (lr 3e-4, 10 epochs): LoRA only 70.76%, AdaptFormer only 71.09%, combined 71.05% (`abl_combined`, the comparison point for the `tune_*` runs): a tie, so placement does not matter. AdaptFormer in the last 6 blocks only is worse (70.17%).
  - Tuning the combined design: label smoothing 0.1 (+1.1) and a lower lr (2e-4: +1.3; 5e-4 is worse) each help; with label smoothing, lr 1e-4 gives 73.02% and 5e-5 is level (73.52%). The head's learning rate matters most: head at 0.5x the adapters' rate gives the **best 5% run, `tune_head_lr_half`, 74.14%** (0.25x level at 74.02%, 2x worse at 71.75%). Head init from 43 images per class raised zero-shot (43.30%) but ended lower (69.98%).
  - So the tuned 5% design ties full fine-tuning with label smoothing (74.14 vs 73.98), but not the tuned full fine-tuning with layer-wise decay (76.26, about 2 points higher at 224 px).
  - Linear probe (`abl_linear_probe`, head only, backbone frozen, same recipe as `tune_ls_lr1e4`): 62.62%, converged. Training the head gives about 70% of the gain over zero-shot (35.70 to 62.62); the adapters add the other 30% (about +10 points, to 73.02).
  - Improvement runs (on top of `tune_head_lr_half`): stochastic depth 0.1 (`imp_droppath`) 74.09%, a tie, though with a lower hold-out loss (1.251 vs 1.325); weight EMA (`imp_ema`) 74.19%, a tie (ahead by up to 1.2 points mid-training, but the cosine schedule catches up); Mixup / CutMix for 15 epochs (`imp_mixup`) 73.97%, a tie (converged, 50% more time); TrivialAugment + random erasing (`imp_trivialaug`) 74.28%, the nominal best but a tie (12% slower, loader-bound). Four regularisers land within 0.3 points of each other, so the recipe has converged: the model no longer overfits much. No combined run is needed (none cleared 0.5 points); `imp_ep15_control` was skipped.
  - Test size (run 22, no retraining): scoring `imp_trivialaug` at 288 px instead of 224 gives **75.99%** (+1.71; 256 px: +1.50), and 76.23% with mirror averaging; latency at batch 1 barely changes (11.4 to 11.7 ms). The only clear gain of the improvement runs. 288 px is the optimum (320: +1.00, 352: -0.22). Submit final models with `--size 288`, and score the full fine-tuning models at the same size before comparing the tracks.
  - **Final 5% model trained (22 Oct): `final_5pct_trivialaug`** = the `imp_trivialaug` recipe on all 45 images per class (no hold-out, leaderboard only). Submit it with `python -m common.submit <run> --team XX --split val --size 288` (and `--split test` in Phase 2).
  - Open runs: 18 `tune_ls_lr1e4_init43` (Nicole), 20 `tune_head_lr_half_init43`, 21 `full_ft_ls_headlow` (fair full-FT comparison with the slower head; it also separates layer-wise decay from the slower head in `full_ft_llrd`); then the 288 px check on the full fine-tuning models (`full_ft_llrd` first) and a final full fine-tuning model on all 45 images per class (`EXPERIMENT_LOG.md` section 5).
