Colab A100 · runs 1 to 53

Five practical problems, and our fixes

Problem
Our fix
1
A T4 GPU was too slow
About 40 times slower than an A100: a run cannot finish
Every run on an A100; on 40 GB the budget is 2.4 h
2
The budget check stopped runs early
Its speed test was too short: a run ended at 0.76 of 1.2 h
Speed tested at steps 100 to 300: next run used 1.13 of 1.2 h
3
Two processes in one folder (run 40)
A second copy wrote to the same run: 8.32 of 10 epochs
A clean re-run under a new name (run 41), one process
4
Reusing a folder name
A finished run’s name loads that old model instead of training
Keep RUN empty, so every run gets its own folder
5
Run 43 dropped
Its final AdaptFormer model was overtaken by 288 px training
Run 42 is our best 5% model; run 30 went to the test set

What we would change in how we worked

If we did it again

1  Screen image size in week 1
Our largest lever, found late: first test-size check 22 Oct, first 288 px training 30 Oct.
common.evaluate --sizes 224 288 320
2  Then tune at 224 px
Faster runs, and most findings carried over: 288 px lifted both tracks by about 2 points.
train_size: 224
3  Re-check the deciding comparisons
At the final settings: the design tie broke at 288 px.

4  Split the hold-out
One photo per class to choose settings, one to report, so no score is judged by what picked it.
